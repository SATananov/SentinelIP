# Legacy Event Export Contract (Phase 23)

Phase 23 makes the existing local event exports safe for spreadsheet and PDF
review, bounded in resource use, and predictable for a one-month offline
review. The routes remain local operator endpoints; this is not remote export
support or a change to the authentication or proxy model.

## Routes and time filters

The endpoints are `GET /export/events.json`, `GET /export/events.csv`, and
`GET /export/report.pdf`. Preset filtering accepts `time_range=15m`, `1h`,
`24h`, or `all`. A custom range supplies both `from` and `until` as RFC 3339
timestamps with an explicit `Z` or numeric UTC offset. The interval is
`timestamp >= from` and `timestamp < until`; `until` must be later than `from`
and the elapsed interval may not exceed 31 days. A custom range cannot be
combined with any explicitly supplied `time_range`, including `all`.

Persisted legacy event timestamps are naive server-local wall-clock values.
Custom timestamp instants are converted to that local wall-clock form for
comparison. Legacy rows cannot distinguish the repeated local hour during a
DST fall-back; this phase does not migrate timestamps.

Severity choices and exact-match `source_ip` behavior are unchanged. Source IP
filter input is limited to 255 UTF-8 bytes; values are neither normalized nor
truncated.

## Completeness and resource limits

Each format uses a bounded `id DESC` query and requests at most its row cap
plus one row to detect overflow. JSON and CSV accept at most 5,000 rows; PDF
accepts at most 1,000. There is no pagination, export total count, or silent
truncation.

Before fetching dynamic event text for serialization, a metadata query checks
SQLite storage types and byte lengths. SQLite `length(CAST(text AS BLOB))`
measures UTF-8 bytes (the database encoding is checked); retrieved values are
then independently checked with strict Python UTF-8 encoding. Each dynamic
text field is limited to 65,536 UTF-8 bytes and the shared aggregate raw-text
preflight budget is 1 MiB. The aggregate budget bounds intermediate text and
keeps worst-case JSON/CSV escaping or PDF XML escaping below the final output
caps with room for structural overhead.

Final output is fully built and measured before the response is returned:
JSON is capped at 32 MiB of serialized UTF-8, CSV at 32 MiB of encoded bytes,
and PDF at 8 MiB of generated bytes. Oversized output is rejected as a whole;
no successful partial file or body is emitted. Rendering may occur in memory
before its exact final byte size is known, but row, field, aggregate-text, and
final-byte bounds apply.

The metadata preflight and value retrieval run in one explicit SQLite read
transaction. The value query is bounded to the selected result set, orders by
`id DESC`, and its IDs are checked against the preflight IDs before rendering.
This gives each export one coherent read snapshot and deterministic insertion
order.

## Error behavior

- `422`: invalid filters, invalid or incomplete custom dates, missing timezone,
  equal/reversed bounds, a range over 31 days, preset/custom conflict, or
  source IP input over 255 UTF-8 bytes.
- `413`: row cap, per-field byte cap, aggregate preflight budget, or final
  response byte cap exceeded.
- `500`: malformed/corrupt persisted required values, invalid encoding, or
  unexpected database, serialization, or rendering failure.

Responses use fixed safe error details; database values, SQL, exception text,
and stack traces are not exposed. Export responses retain `Cache-Control:
no-store` through `local_management` on both success and error. That guard
continues to require direct loopback/local-host operator access and to reject
proxy-forwarded requests and sensor credentials.

## Rendering safety

CSV uses normal `DictWriter` quoting for CSV structure. Separately, every
exported string cell (timestamp, source IP, username, event type, severity, and
message) gets exactly one leading apostrophe when the first character after
leading ASCII space, tab, carriage return, or newline is `=`, `+`, `-`, or
`@`. Original whitespace and content remain intact. Numeric `id` and
`event_count` are unchanged, and a NULL username remains an empty cell.

Every dynamic event value inserted into a ReportLab `Paragraph` is XML-escaped
and therefore rendered as literal text. Trusted static application markup,
including the report subtitle's intentional `<br/>`, remains markup. Dynamic
values in ordinary table cells remain literal cells.

## Successful response behavior

- JSON keeps its object shape (`generated_at`, `count`, `filters`, `events`),
  remains inline without `Content-Disposition`, and returns `count: 0` with
  `events: []` for no matches.
- CSV always includes its header; no matches produce a header-only attachment
  named `sentinelip-events-YYYYMMDD-HHMMSS.csv`.
- PDF remains an `application/pdf` attachment named
  `sentinelip-security-report-YYYYMMDD-HHMMSS.pdf`; no matches produce a valid
  PDF containing the existing no-events message.

Filenames are generated by the server and do not contain filter or date input.
All three routes remain local-only, and Phase 23 adds no remote or sensor
export path.

## Schema, verification, and scope

The schema remains version 45. No migration or index was added. Local
`EXPLAIN QUERY PLAN` output is structural evidence only, not a production
latency claim. Date-only and date-plus-severity shapes scan `events`; date plus
source IP uses the existing `idx_events_threat_window` index and a temporary
B-tree for `id DESC`; adding severity keeps that source-IP access path. No new
index was justified by the local query plans.

The repository's authoritative full backend suite has a known TestClient/
AnyIO stall before router entry (including `/health`), reproduced against the
clean pre-23B baseline. A stalled run is incomplete verification, not a pass
and not evidence of an export regression. Phase 23 focused backend and
frontend checks are reported with the close-out review; no full-suite pass is
claimed where the suite did not complete.

Out of scope for Phase 23: retention cleanup, Incident Review changes, sensor
flow changes, remote exports, pagination or background exports, and Vite
bundle optimization. Normal event-list behavior, detector logic, and
authentication/proxy policy are unchanged.
